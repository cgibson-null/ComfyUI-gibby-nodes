## Context system

The core idea: a **Context** node is a bag with sampling and metadata related values that can be overridden. Has Any slot added with idea of using Any Pipe node. Every field is optional. Spiritual inheritor of [rgthree's](https://github.com/rgthree/rgthree-comfy) Context.

**Context Loader** - loads model(ckpt or diff)/clip/vae(s - for audio too), sets prompts and sampling params, and outputs a ready-to-use context. The starting point of most workflows. Detects model category and creates appropriate latent for it (flux2/flux3/fibo2). Spiritual inheritor of [Efficient loader](https://github.com/jags111/efficiency-nodes-comfyui).

**Context Override** - provides widgets to override context values. Toggles let you choose which categories to override. Useful when you want to separate setting per sampling stage (steps 1-3 higher cfg, 1st prompt, remaining steps - 1cfg, 2nd prompt; etc)

**Sampling Parameters (Context)** - acts like override for sampling parameters.

**Merge contexts** - dynamic `context1…context10` inputs, single context output. Takes the 1st context as base, then goes through the other provided contexts in order and overrides its values with theirs - a value overrides only when it is set (None, zero and empty string keep the base's value).

For ggufs use **Context** and connect loaders to it, then use **Context Override** or **Sampling Parameters (Context)** to provide initial context values.

If **Context Loader** and **Context Override** are provided with image and/or audio, they are encoded using respective VAE, and if both provided - combined into AVlatent. Respective masks also applied, allowing easy i2i or masking audio to generate audio-driven video.

## KSampler (Context)

Unifies native KSampler, KSamplerAdvanced and KSamplerCustom nodes' features.

Use **inputs** to override context values (override happens first, so output context will contain same values)

**Latent** used in priority:
- provided latent;
- encode image and/or audio with provided masks using respective VAE, combine if both;
- create empty latent based on context width and height, respecting model type (flux2/flux3/fibo2).

**Steps:** widget `steps` overrides context's steps and refiner_steps when >0. refiner_steps are used for i2i. start/end inside defined by widget or context step will ignore refiner_steps.

**Start / end step:** three modes per value:
- `0 < value < 1` - fraction of total steps (e.g. 0.5 = halfway)
- `value < 0` - offset from the end (e.g. -5 = last 5 steps)
- `value ≥ 1` - absolute step number

**Denoise:** only applies when an image is present, otherwise forced to 1.0. Always slices the schedule, so start/end step narrow the denoised range instead of cancelling the denoise. flux2 models sample with the Flux2 schedule for the sampled size, denoise takes its low-noise tail exactly like `Flux2Scheduler` -> `SplitSigmasDenoise` (`low_sigmas`); flux3 keeps its own constant shift and the context's scheduler.

**CFG schedule:** optional link-only float input that replaces the context's cfg on every sampling step - one value per step of the context's steps, from `String to Float List`, a float batch, or a single float. Past its end the last value is held for the remaining steps, so `3, 2, 1` over 5 steps samples 3, 2, 1, 1, 1; extra values are ignored. Like the travels, it follows the context's step numbers, so start/end step shift it with the steps they slice (`2, 1` with start_step 1 samples at 1); each crop-inpaint crop samples it from the first value. The context's cfg is left alone, so the verbose log and saved metadata keep it. Sampling is split into one run per stretch of equal values, each run sampled at its own cfg, so `6, 5, 4, 1` over 10 steps is four runs (1+1+1+7 steps) where comfy drops the negative for the 1.0 stretch - those steps cost one model pass instead of two, which is the whole saving and the whole cost: 7 steps at cfg 1 is 7 steps with no guidance, only sane on a checkpoint that is fine there. The runs chain through comfy's own leftover-noise handoff, so the latent is never re-noised at a seam, but a sampler that injects noise per step (`lcm`, the ancestral and `sde` ones) starts a fresh noise stream on every run and a multistep one (`dpmpp_2m` and friends) restarts its predictor, so a split schedule is not the same image as one call at the same cfg per step; `euler` has neither problem. Verbose logs the runs, and a schedule that never changes value is one call. Every run's own cfg is what decides about the negative, so the 1.0 stretch is single-pass whatever the context's cfg says - but keep that cfg above 1: at cfg 1 the context nodes build an unused (zeroed) negative, and the runs above cfg 1 would guide away from that instead of your negative prompt.

**Decode:** on by default. Decodes the output latent to image/audio/both and removes latent from context. An image whose size is not a multiple of the VAE's downscale ratio is pre-scaled to it before encoding, and the decoded image is stretched back to the original size, so the content stays aligned with the original. Disable to skip decoding in case you're chaining ksamplers (wan high pass).

**Latent output:** the latent the returned image was sampled from - the sampled latent, or the last iterative step's latent. Crop-Inpaint samples each crop at its own size, so its latent output is the latent of the inpainted area (the last region's when the mask splits into several), at the size that crop was sampled at, never the whole image.

**Options:** connect options nodes to the `options` input - **Crop-Inpaint options**, **Iterative Options**, **Lora Travel options**, **Tiled VAE options**, **Clear VRAM options**, **Color Match options**, **DyPE options**, or **Merge KSampler Options** (dynamic `option1…option10` inputs that append several options lists into one).

**Crop-Inpaint options** - allows crop area per mask, configure boundaries and resolution, and inpaint it at proper size, then paste back onto original.

**Iterative Options** - sample for set amount iterations, can upscale; an optional target size image overrides the upscale factor and sets the final size. `latent_upscale` grows the latent between steps instead of decode -> upscale -> encode, so the VAE runs at the ends of the run; the upscale model is an image model and is not used then.

Crop-Inpaint options and Iterative Options are inclusive, meaning can be used together. Both ideas from [Impact-Pack](https://github.com/ltdrdata/ComfyUI-Impact-Pack)
**Lora Travel options** - dynamically change loras strength per step; str values in node are multipliers for value set in lora loader, unless it's 0 - then they are applied as actual str; can be used per iteration.

**Clear VRAM options** frees VRAM like [Easy-Use](https://github.com/yolain/ComfyUI-Easy-Use)'s Clean VRAM Used.

**Color Match options** - after sampling (a run from a provided image, crop-inpainting, or the final iterative step) the result's color is matched back to the original with Transfer Color (`strength` 0 = no match).

**DyPE options** - needs the [DyPE](https://github.com/wildminder/ComfyUI-DyPE) pack. dype/sega patch the model for high-resolution generation, so every other feature applies to them: the patch is re-applied per sample at the size actually being sampled, which makes it combine with the iterative upscale, and it never leaves that step.

**Tiled VAE options** - self-explanatory.

Supports prompt travel/scheduling, whatever it is called, from a1111/forge webui:

[a:b] - alternates between prompts a and b each step.

[a:b:3] or [a:b:.4] - uses prompt a at start, switches to b at step 3 or total_steps*.4

[a:b:8:4] - crossfade, a up to step 5, step 5 a at str .875 b - .125, step 6 - a:.75, b:.25, step 8 - both .5, step 9 a:.375, b:.625, step 12 - prompt b

[a:b|3] or [a:b|.1] - iteration like [a:b] but instead of alternating each step, does it each 3 steps or total_steps*.1

Groups nest, and only square brackets travel: `(prompt:1.5)` stays ComfyUI's weight syntax and is passed through untouched, colons and all.

The context conditions with the first prompt of the plan - never the literal `[a:b:3]` text - and only the prompt that travels is encoded; the other keeps the context's own conditioning. Each unique prompt of the plan is encoded once and cached with its text encoder (last 8 per clip), so re-running an unchanged prompt skips the text encoder entirely.

## Other nodes

**Lora Loader** - spiritual successor of [rgthree's](https://github.com/rgthree/rgthree-comfy) PowerLoraLoader initially made by Divine. Nodes2.0 compatible and extends functionality. The prompt carries the loras that actually get applied - the rows the node would skip (off, empty, strength 0) stay out of it, and so does the filter box - because the prompt is what the backend caches on: turn a lora off, add one and leave it off, or type in the filter and the cached result is reused and the run finishes instantly, while switching one on re-runs it. The workflow still saves every row.

**Any Switch** - [rgthree's](https://github.com/rgthree/rgthree-comfy) Any Switch but with dynamic number of inputs.

**Any Batch/List** - dynamic-input batch of any type: `Batch` concatenates the connected inputs the way Batch Images does (tensors along dim 0, conditioning and other lists joined), `List` outputs them as a Python list like `Make List (Any)` from [Impact](https://github.com/ltdrdata/ComfyUI-Impact-Pack).

**Any Count** - how many items a value holds: the batch size of a tensor or latent, the length of a conditioning or a list, 1 for a single object. Nothing connected and a null both count 0, so an optional branch can be measured without being wired - the case [Essentials'](https://github.com/cubiq/ComfyUI_essentials) `Batch Count` can't do, as its input is required.

**Show Any** - [EasyUse's](https://github.com/yolain/ComfyUI-Easy-Use) `Show Any` for nodes 2.0: several values drag into the one slot and each gets its own read-only row, a list is shown as one row per item, and a tensor, latent or model is named by its shape, dtype and class instead of a JSON dump or a wall of numbers. What was shown is saved with the workflow - and written into the workflow embedded in the output image - so it comes back without a re-run.

**Pipe Any** - bundles up to 10 `Any` values into a dict. Mostly inspired by [Crystools'](https://github.com/crystian/ComfyUI-Crystools) one, just unified into single node like context instead of in/out split.

**Fast Groups Muter / Bypasser / Toggle** - like [rgthree's](https://github.com/rgthree/rgthree-comfy) but with cookies - have mass toggle, enable, mute/bypass; better settings window (actual window, not menu) with color picker (not text input). Toggle merges bot options with a toggle between bypass/mute.

**Group Header Toggles** - three small buttons (queue / bypass / mute) in the top-right corner of each group header. Active by default, available in settings. Stolen from [rgthree](https://github.com/rgthree/rgthree-comfy).

**Resize Image / Empty Latent (Context)** - creates empty latent or resizes connected image/mask allowing to keep proportions. Optional vae overrides the context's vae; encoded_latent outputs the image encoded with it (empty_latent when no image or vae). Always outputs a context - without a context input it creates a new one with width, height and the empty latent. `Enable preview` toggle (off by default, hidden while load image / crop image is on) writes and shows the output image's temp preview in the node on execution; off writes no preview file at all (while load / crop is on the preview is always written - downstream crop views read the context's image from it).

**Reference Latent (Context)** - faster flux2/klein/flux3/fibo2 references, rescale all to the `megapixels` target then to `scale` (0 = own size), floored to the VAE's downscale ratio (2x for qwen image 2.1, so the latents splice at the vision slots). `ref_latents` (on) VAE-encodes them and references them on the conditioning - the edit path the edit models were trained for; turn it off for a t2i model that only has the latent-concat path by accident (krea). A text encoder with a vision tower (qwen image, qwen image 2.1, krea2, mage, boogu, ideogram4, fibo 2.0) also sees the images and the prompts are re-encoded with them, at `vl_megapixels` (0 = the VAE-sized image; qwen image 2.1 always shares one size so every vision slot covers 2x2 latents, fibo 2.0 because its tokenizer does its own 768px / Qwen3-VL-grid resize) - that is how a model with no edit path conditions on a reference at all. Flux3's encoder is text-only by training, so it takes latents alone. A negative the context carries is kept as it is at the context's `cfg` 1 (it only gains the references) - cfg 1 never runs it, so a turbo model (fibo 2.0) pays for no re-encode and a negative built outside the prompts survives the node; only a negative that exists as prompt text alone becomes the zeroed positive, like KSampler (Context) makes it. HiDream-O1 and SenseNova read the reference as a raw image rather than a latent, so they get the resized image itself and need no VAE. p-h3-image and MiniMax-H3-Image take them as `minimax_refs` instead - the {kind, latent_h, latent_w, latent} blocks the DiT re-injects every step - next to the Qwen vision copies that fill the `<Picture n>` slots, each copy sized on the model's own grid (p-h3-image: the vision pixel budget and the generation area; MiniMax-H3-Image: a 1024 short edge for Qwen, 1024-2048 for the VAE) after `megapixels` and `scale`; p-h3-image wants its `Edit <Picture 1>. ` prefix written in the prompt, and `tiled_vae_options` does not tile them. `ref_ctx_img` additionally references the context's own image at its own size (always when no image is linked, otherwise only when enabled); with no context image the first image becomes the context image and is stored back on the output context. `tiled_vae_options` takes the same Tiled VAE options node the sampler takes and encodes a reference at or above `above_megapixels` in tiles instead of whole - what a huge image costs with `megapixels` 0 or `ref_ctx_img`; only that option of the list is read. A media pipe's reference images are referenced too - the wired images append to them in the output pipe. Without a context input it is just a media pipe creator: the wired images append to the pipe and the context passes through empty.

**Mask/Segment (Context)** - detects or segments objects on the image (connected image wins over the context one) and stores the resulting image and mask in the context; the context's model and clip pass through untouched. A mode selector reveals the widgets of the chosen approach: `bbox` (ultralytics detector), `segm` (SAM refined by the detector's boxes), `sam3` (the selected SAM3 checkpoint, which can track through a batch of frames; the tracker is seeded by the first-frame detection, or by a connected mask instead, which skips that detection outright - one mask per object, so a merged mask tracks as a single object). The mask is stored as the detection produced it - clean it up, grow it or preview it with **Mask Edit (Context)**. Also outputs crop info for pasting results back with **Image Paste By Mask (Batch) (Context)**.

**Mask Edit (Context)** - the mask manipulation the detection and crop nodes used to carry, in one node. The mask is cleaned first (`remove_isolated_pixels` drops isolated specks, `fill_holes` closes the holes the mask encloses), its edge is then feathered by `mask_blur` pixels and it is grown and inverted (`mask_grow` / `mask_invert`, the native Grow Mask / Invert Mask), so growing enlarges what is left instead of the specks. `remove_bg` replaces the unmasked area with `rembg_color` (an alpha 0 color makes it transparent instead - RGBA output). `preview` shows the image with the mask tinted in `mask_color`; a batch of frames previews as a video at `preview_fps`. Connected image/mask win over the context's; the output context carries the edited image and mask. A crop info that describes the image being edited is refreshed to the edited mask, so a paste back honors the edit; a crop's own - whose mask is the full frame the crop came from - does not match and passes through untouched, so **Image Paste By Mask (Batch) (Context)** still pastes onto the frame the crop was taken from.

**Image Crop By Mask (Batch) (Context)** - crops each image by its own mask (image i by mask i); every crop is scaled up until it fills the total size, so subjects keep a consistent scale across the batch - when a crop's shape differs from the canvas its edges are trimmed. Optional temporal stabilization for video batches: constant crop size per shot and a smoothed crop center, with cuts detected from mask jumps. The mask is cropped as it arrives - grow, invert, feather or knock the background out of the crop with **Mask Edit (Context)**. Outputs the crop info for pasting back; with a context, its image and mask are used when none are connected and the output context carries the cropped image, mask and crop info.

**Image Paste By Mask (Batch) (Context)** - pastes images back onto the originals by mask: from a crop info (the exact inverse of the crop), or standalone with images_original and masks, where each mask's bbox is the paste area; when the batches differ, the smaller size wins. With composite on it instead pastes like Image Composite Masked: the pasted image is resized to the original's size when it differs and a source-sized mask is applied to it (no mask pastes opaquely).

**Split Tiles (Context)** - splits the context/connected image into a batch of uniform, overlapping tiles (rows x cols, overlap as a fraction of the tile size) and outputs the tiles, a matching batch of masks for the Crop-Inpaint options, and the tiling info. The output context carries the tiling info too. Stills only.

**Combine Tiles (Context)** - recombines a batch of tiles from the tiling info into the image: the layout is scaled to the tiles' size (which may be larger than at the split - the upscaled case) and the tiles are crossfaded across the overlap bands. Pair with Split Tiles to sample or upscale a still tile by tile.

**Image Saver (Context)** - saves image with a1111 metadata (civit compatible) created from context values. `save_metadata` off writes no generation-parameters block and does no hashing or Civitai lookups; the workflow embed and the JSON sidecar keep their own toggles. Ripoff from [ImageSaver](https://github.com/alexopus/ComfyUI-Image-Saver) pack.

**SeedVR2 Upscale (Context)** - the entire [SeedVR2](https://github.com/ByteDance-Seed/SeedVR) upscale in one node: resize, pad, tiled VAE encode, sample with the encoded latent as the conditioning, decode, then align and color-correct the result to the resized input - replaces Pre-Process SeedVR2 Input, Apply SeedVR2 Conditioning, Post-Process SeedVR2 Output, the KSampler and the tiled VAE nodes. Model and VAE lists are filtered to the seedvr files; `None` takes them from the context. Target size is `megapixels` (0 = the input's own size) times `scale_factor`, like **Resize Image / Empty Latent (Context)**, and a `target_size_image` overrides both with its own size, like **Iterative Options**. `chunking_mode` samples a video a temporal chunk at a time (none / auto sized by free VRAM / manual `frames_per_chunk`) with `temporal_overlap` crossfaded at the merge - Split and Merge SeedVR2 Latents. Sampling is euler/simple at cfg 1 and denoise 1.0, `steps` 1 - the step the model was distilled for. The tile widgets are VAE Encode (Tiled)'s and drive the encode and the decode. `clean_vram` frees VRAM before the model loads (off by default).

**RelayVSR Upscale (Context)** - the entire [RelayVSR](https://github.com/kopperx/RelayVSR) video upscale in one node: the keyframe conditioning, the one step of sampling the model is trained for, and the Flash decoder - RelayVSR Conditioning + a KSampler + VSR Decode. Model and VAE lists are filtered to the relayvsr files and must be the same factor; `None` takes them from the context. The model decides the size: every frame is upscaled by the model's own x2/x4 factor from the input's own resolution, only every 15th frame goes through the Wan model and the decoder restores the rest, so there is no target size to set and nothing to tile. Sampling is fixed at euler/simple, 1 step, cfg 1 and denoise 1.0 - at one step every usable scheduler starts at the same sigma, there is no prompt to negate, and the model is distilled for that step - the seed widget (default 0) being the degree of freedom the sampler keeps since the step starts from pure noise; `detail` is how much of the detail the decoder adds to the bicubic upscale of each frame is kept (0 = plain bicubic). The context's audio is output untouched - the upscale is spatial only and keeps every frame, so the soundtrack still lines up with the result.

## MiniMax H3

Idea of it is to use single reference list for any amount of passes. if you for example decide to 2nd pass upscale with h3, you have to recondition to avoid errors, which would mean duplicating conditioning node and potentially reattaching references. H3 Pipe approach resolves that issue, establishing single source of truth.

**H3 Pipe Create** - builds a config dict (H3 Pipe) from reference images/videos/audios, keyframes, prompt, and dimensions. Stores raw tensors, no encoding yet. The H3 Pipe is a media pipe - `ref_images`, `keyframes` with their positions, `ref_videos` (+ soundtracks), `ref_audios` - plus the h3 params, so the same dict feeds Reference Latent (Context) and Generate as well. Picture references are introduced to the text encoder as `<Picture n> (reference): ` rather than core's `<Picture n>: ` - that one is the same text as first/last-frame conditioning, so a run with exactly two references was reproduced as the video's ends; a prompt still names them `<Picture n>`. Keyframes anchor the video at given positions: `indices` takes a comma-separated list - an integer is a frame index (negative counts from the end, -1 = last), a decimal is a percentage of the video (0.5 = middle); `even_distribution` spreads the full batch (first/last frame included) evenly from 0 to the last frame; `loop` anchors a duplicate of the first keyframe at the last frame. first/last frame join the batch at its start/end. Those two end instants take one image each: `first_frame` anchors frame 0 and `last_frame` the last frame, and a keyframe anchored there too is dropped when the pipe is applied, anchor included - two images pinned at one frame carry the same time coordinate and different pixels, which the model resolves by rendering a blend of them, and the fl2va conditioning has room for two prompt pictures at most (`<Picture 1>` being the video's first frame, `<Picture 2>` its last). `loop` keeps the last frame ahead of `last_frame`, since ending where the video started is the stricter demand. **keyaudio** pins sound onto the clip's own timeline - `Add Guide`'s audio input, in the pipe: several tracks go in as a list of audios (**Any Batch/List**, List mode) or as one batched AUDIO - a list keeps each track's own length, which is what you want, since a padded track would be performed as silence; each track rides as the audio half of a keyframe, so the model *performs* it at that instant (a lip sync point, a beat, a line of dialogue) instead of only imitating it the way it imitates `ref_audio`. `indices_audio` places the tracks with the same position spec, paired in batch order, and a track left off the list anchors frame 0. A track longer than the room left to it is cut where the next track starts or where the clip's audio ends, because two pinned windows cannot share an instant, and a track landing on an instant another track already owns is dropped rather than blended; pinning past the end of the clip's audio is an error. `even_distribution` and `loop` are keyframe-only - a pinned window has no fixed length to distribute, since it is as long as the waveform is. Pinned audio needs the audio VAE at apply time, and it costs no frames: audio anchors are rows, not timeline. Shamelessly stolen from [H3-Hybrid-Cond](https://github.com/kitsune123150/minimax-h3-hybrid-cond).

**H3 Pipe Apply** - encodes pipe. target_width and target_height override the pipe's width and height for the keyframes and the latent, which is required for i2v 2nd pass upscale. A context that already carries an H3 AV latent - **H3 Timeline**'s target, an **H3 Latent Upscale** pass - keeps it and only gains the conditioning, so the node never throws away a latent another node built; an image latent or no latent still gets the pipe's empty AV latent. `drop_ref_images` / `drop_keyframes` / `drop_keyaudio` / `drop_ref_videos` / `drop_ref_video_audios` / `drop_ref_audios` prune the pipe before applying; without clip/vae (wired or from the context) it just outputs the pruned h3_pipe.

**H3 Timeline (Context)** - continues an existing MiniMax H3 clip instead of starting a new one: `extend` generates after it, `prepend` before it, `loop` bridges its end back to its start so clip + result plays as a seamless loop, `insert` opens a gap inside it for a new scene and leaves everything either side untouched. The source clip stays inside the target latent with its denoise mask at 0, so the sampler composites it back unchanged and the model reads it as its own context at its real time coordinates - not as keyframe anchors it has to reproduce, and not as a reference, which it imitates rather than continues. Only the gap is denoised, so nothing comes back to trim off a chain and there is no windowed-edit rig to run. `segment_frames` is how much to generate; `overlap_frames` is how much of the clip to keep as the model's starting point (its tail for extend and loop, its head for prepend), and `loop_end_frames` sets the arrival side of a loop separately from the departure side - rows a mode does not read are hidden. Everything sits on the video VAE's grid - it encodes 17-frame chunks into 5 latent steps and the 1,4,4,4,4 frame pattern restarts every 5 steps, so a block only lands where its own cycle phase matches the position it is given and a clip's latent must stay 5x+2 steps long. That is why a loop's gap is 17x+9 frames where the other modes take 17x: the loop's two kept blocks each claim 5x+2 steps of the total, and the widgets step by 17 so the values offered are the ones that fit. The soundtrack follows the picture at the same boundaries and is kept, not regenerated, wherever the picture is kept, so a loop or an insert leaves the original audio exactly as it was and only the new span gets new sound; with no source audio the model writes the whole track instead. Feed it the clip's `av_latent` - a sampler output, not the context's latent, which is the empty target - for the kept parts to stay bit-exact, or its `image` and `audio`, which cost a VAE round trip on those parts. `vae` / `audio_vae` override the context's. The `h3_timeline` output (also on the context) is what H3 Timeline Assemble reads: `mode`, `fps`, `source_frames`, `segment_start` / `segment_frames` - where the model's work sits in the sampled output - `trim_head` / `trim_tail` - how many frames of the sampled output are kept source rather than new content - and `audio_trim_head` / `audio_trim_tail` in 40 Hz audio steps, because the picture and sound clocks round differently and a join one step off is a click. `insert` reports 0/0 trims because it hands back the whole clip. `kept` lists every source block as `latent_frame` / `frames` / `source_frame` plus `latent_audio` / `audio_steps` - where it sits in the new clip in both clocks and where it came from - so a later node can put source content back into that latent without re-deriving the mode's layout. Self-check: `python tests/test_h3_timeline.py`.

**H3 Timeline Assemble (Context)** - the other half: takes the decoded sampled output and the `h3_timeline` dict and delivers the finished clip, cutting the generated span out of the decode and joining the original clip to the side the mode says - after it for `extend` and `loop`, before it for `prepend`, nothing for `insert`, whose decode already is the whole clip. The original's frames and soundtrack ride inside the dict, so nothing has to be wired back a second time; `source_image` / `source_audio` stay there as overrides. Picture and sound are joined at the exact audio cut points from the dict, so the seam cannot drift, and a join that starts near-silent is reported as the generation rather than the splice. With Color Match options connected, only the span the model made is matched, frame by frame, to the kept frame it continues from, so a new scene takes the original's grade and keeps it as it goes - matching the span's pooled statistics instead averages a progressive drift into a hard step at the seam - while the original itself is never touched.

**H3 Timeline Pin (Context)** - the step between the extension and the pass that upscales it. A latent upscale re-samples the whole latent, so the clip's own frames come back as the upscaler's guess at them; this takes the first pass's latent after the upscale as `upscaled_av_latent` plus the source clip at that same resolution - as `av_latent`, or as `image` and `audio` for it to encode - pastes the source's real picture and sound back over exactly the blocks `kept` names, and sets the denoise mask to 0 there, so the sampling pass that follows enhances only the span the model generated instead of softening the original at the ends of a sharp middle. Only the `kept` blocks are read from the source, each encoded on its own - which is how H3 Timeline encoded them on the way in, so the two agree instead of differing by where the video VAE's 17-frame chunks fall. The whole audio stream is masked off - an upscale pass is a video operation, so sound comes through untouched.

**H3 Latent Upscale (Context)** - the core MiniMax H3 Latent Upscale With Model node, its loader and the size math of **Resize Image / Empty Latent (Context)** in one node: the video half of the clip's `av_latent` is upscaled in the latent space, with no decode, resize and re-encode in between. The model list is the `latent_upscale_models` files mentioning `minimax_h3`. Target size is `megapixels` (0 = the latent's own size) times `scale_factor`, floored to H3's 32 pixel canvas grid. The audio half passes through the upscaler unchanged, and `retain_audio` (on by default) also masks it off on the output latent - 0 over audio, 1 over video - so the sampling pass that follows sharpens the picture and hands the soundtrack back exactly as it came in; off, the latent is unmasked and both streams are regenerated. The upscaled latent, its size and the context carrying it are all output.

**H3 Mask Latent (Context)** - per-frame inpainting on an H3 AV latent: put a MASK on the latent and the sampler re-denoises only the masked area, returning everything else bit for bit. Core cannot do this - `Set Latent Noise Mask` stores a plain tensor, and the sampler then masks the video stream alone while the audio stream gets an all-ones mask, so the whole soundtrack is regenerated. This builds the mask for both streams: the picture mask is max-pooled onto the latent grid, which is how the model pools the mask over each 2×2 DiT patch anyway, so a thin mask survives the downsample, and the soundtrack follows the picture in time - an audio step is re-denoised when any frame it covers is masked. Give it one mask per pixel frame, one per latent step, or one for the whole clip. Feather the edge on the Image Paste By Mask (Batch) (Context) that follows, where it is in pixels, not here. Wire it **after** H3 Timeline, never before: that node writes the mask that keeps the original clip and opens the gap, and this one adds its area on top, so a picture mask can be confined to the span being generated. A mask can only add areas to regenerate - switching one off would leave the gap as the nothing the timeline put there, black picture and silence. Over a latent that already carries a mask the soundtrack keeps that mask's policy, so only the opened gap gets new sound and a picture mask running the length of the clip does not rewrite the whole track - which is what makes it usable in a relay loop, where the same clip is re-sampled pass after pass.

**H3 Chunk (Context)** - sample a long clip in temporal windows, so a v2v or inpaint pass never holds the whole thing at once. Give it the clip **either way**: as an `av_latent`, which it slices, or as `image` + `audio` straight off a video loader with `vae` + `audio_vae`, which it encodes - and only the window, never the whole clip, so the VAE stays small too. A `mask` over the whole clip is pooled onto the window as the denoise mask, and unioned with whatever mask the latent already carries; a mask can only add areas to regenerate. The window's first `overlap_frames` are carried in at mask 0 - kept bit for bit, read by the model as the motion leading into the window, and trimmed off the output as the loop's overlap. Wire **`previous_av_latent`** - the chunk before this one, straight from the sampler - and that chunk's own tail supplies the context band instead of the untouched source, which is what a character replacement needs: the model continues from the character it already put there. `frame_offset` then has to be the loop's `accumulated_count`, which is what lands that tail in the right place:

```
chunk 0: window    0- 175 (52 steps), context    0-   0 from source,          output    0- 175 (175)
chunk 1: window  136- 345 (62 steps), context  136- 175 from previous chunk,  output  175- 345 (170)
chunk 2: window  306- 515 (62 steps), context  306- 345 from previous chunk,  output  345- 515 (170)
```

The **`overlap_frames`** output is the value the input actually got snapped to - the frames this window shares with the one before it. Wire it into **Image Batch Extend With Overlap**'s `overlap` (or Close Tensor Loop's `overlap_frames`). Get this wrong and the seam shows: trim 34 when the node used 39 and the output starts with 5 kept frames from the previous chunk before the new ones, then jumps.

The soundtrack is masked off across the window: it comes through untouched, so no chunk can rewrite audio the previous one already delivered, and the clip's own track stays valid end to end. The sampled sound rides inside `av_latent`; the **`audio`** output is the input track cropped to the same frames as `image`, context band included, so the two join on the same `overlap_frames` (it is None when the clip came in as a latent with no soundtrack wired). `image` and `mask` are the **whole clip's** (one per pixel frame, not a window) and the node crops them for Image Paste By Mask (Batch) (Context). Everything is on the video VAE's grid, and both constraints hold at once: a window starts only where its own 17-frame cycle starts, because the model numbers its steps from 0 of the tensor it is handed (`_video_t_spans`), and runs 17k+5 frames, because that is as much as the VAE can encode. So `chunk_frames` snaps to a multiple of 17, `overlap_frames` to 17k+5, and `frame_offset` back onto the grid:

```
window 0: frames   0-124 (124 in, 37 steps), output   0-124 (124 out)
window 1: frames  85-243 (158 in, 47 steps), output 124-243 (119 out)
window 2: frames 204-362 (158 in, 47 steps), output 243-362 (119 out)
window 3: frames 323-413 ( 90 in, 27 steps), output 362-413 ( 51 out)
```

Drive it with KJ's **Open / Close Tensor Loop**: `accumulated_count` → `frame_offset`, the decoded window → `processed`, overlap **start** with its `overlap_frames` wired from this node's output.

The **`h3_pipe`** output carries only the window's `width`, `height` and `length` - the frames its latent actually covers, context band included - for **H3 Pipe Create**'s `h3_pipe` input. Create keeps them while its three widgets still hold their own defaults (`override_config` writes the widgets over them), so every window is conditioned at the size it is sampled at, which matters once a latent upscale has changed it from the clip's. Keyframe and keyaudio positions in that pipe resolve inside the window: `-1` is its last frame, a percentage is of its own span, and an absolute frame index past it is refused.

## LLM Connect

Nodes for talking to a llama.cpp server / llama-swap proxy (OpenAI-compatible API); Unsloth Studio works too.

**Connectivity** - server URL + model dropdown (auto-fetched from the server's /v1/models, cached per URL, Reconnect button) + optional API key. `keep_alive` 0 unloads the model right after each response; other values are the server's idle policy.

**Sampling Options** - per-request sampler settings (temperature, top_k/top_p/min_p, mirostat, repeat penalty, stop, n_predict, seed, reasoning budget/effort), each field gated by an enable toggle - only enabled fields are sent.

**Unsloth Load Options** - per-load parameters (context size, speculative/MTP, KV-cache quant, extra server flags); Generate prices them with Unsloth's own validate / estimate-memory probes, then applies the priced command via Unsloth's /load API (local copy first, else the Hub repo) - one serving slot, and a context Unsloth says will not fit is fitted instead of failed; ignored on llama-swap, where those flags are fixed at server start (config.yaml cmd, one entry per variant).

**Generate** - single-shot text generation with auto-growing image/video reference slots (videos sampled to still frames, first + last always included; references go out as JPEG, since a vision model reads a picture at its own patch grid and the lossless PNG of a render is only request size - enough of them to hit the server's body limit, an HTTP 413); prints a tokens/sec line with the time it took for every run. Can take a media pipe - its refs and keyframes are sent to the model, labeled as such - and outputs a media pipe carrying the wired refs and the generated text as its prompt.
